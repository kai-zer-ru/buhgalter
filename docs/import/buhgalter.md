# Формат Бухгалтер (импорт / экспорт)

Нативный CSV для переноса учёта между инстансами Buhgalter. Это не Cubux: файл начинается с `#BUHGALTER,1` и состоит из секций `#SECTION`.

Для выгрузки в Cubux используйте формат Cubux в UI экспорта или `GET /api/v1/export?format=cubux`.

---

## Структура файла

Кодировка: **UTF-8 с BOM**.

```
#BUHGALTER,1
#SECTION,accounts
id,name,type,bank,initial_balance,...
...
#SECTION,transactions
Тип,Дата,...,Время,Магазин,Теги,Комиссия,ID,Подписка
...
```

Секции (порядок при экспорте): `profile`, `accounts`, `categories`, `subcategories`, `merchants`, `tags`, `transactions`, `credits`, `credit_payments`, `debtors`, `debts`, `debt_links`, `subscriptions`, `recurring`, `budgets`, `templates`.

Пустая секция всё равно пишется с заголовками.

## Операции (`transactions`)

База колонок совпадает с [Cubux](cubux.md), плюс:

| Колонка | Формат | Назначение |
|---------|--------|------------|
| `Время` | `HH:MM` или `HH:MM:SS` | Время операции (UTC, как в API). Без колонки дата ставится на 12:00 UTC |
| `Магазин` | имя | Создаётся, если нет в справочнике |
| `Теги` | имена через запятую или `;` | Создаются, если нет в справочнике |
| `Комиссия` | сумма | Комиссия перевода (ноги комиссии в CSV нет — она на строке перевода) |
| `ID` | UUID исходной операции | Для связей кредитов, долгов, подписок |
| `Подписка` | имя | После импорта секции `subscriptions` привязывается к операции |

Файл Cubux без магии `#BUHGALTER` по-прежнему принимается пресетом `cubux` (только операции). Плоский CSV с колонками Cubux+время/магазин/теги — пресетом `buhgalter` без секций (счета, кредиты и справочники из него не восстанавливаются).

Перевод в секции `transactions` — одна строка. В БД по-прежнему две ноги (`transfer` out/in); `GET /transactions` считает обе. В превью импорта `valid_rows` — строки файла, `transfer_rows` — сколько из них переводы, `list_rows` = `valid_rows` + `transfer_rows` (сколько записей будет в журнале).

## Профиль

Секция `profile`: `timezone`, `currency`, `language`. При импорте часовой пояс (и при наличии — валюта и язык) записываются пользователю-получателю. Без секции остаётся пояс нового пользователя (`Europe/Moscow` по умолчанию) — плановый остаток подписок тогда считается в другом календарном месяце.

## Счета

Секция `accounts` задаёт тип (`cash` / `bank` / `credit_card`), банк, **начальный остаток**, лимит кредитки, основной счёт, статус, автопополнение. Операции накатываются поверх `initial_balance`, поэтому балансы после полного переноса совпадают с источником (в том числе у кредитных карт).

## Импорт

`preset=buhgalter` в `POST /api/v1/import/preview`, `POST /api/v1/import`, `POST /api/v1/import/jobs`.

Если файл начинается с `#BUHGALTER`, пресет переключается на `buhgalter` автоматически (кроме `custom`).

Порядок: счета и справочники → операции (с дедупом по содержимому) → кредиты, долги, подписки, периодические, бюджеты, шаблоны. Кредиты и долги вставляются без повторного создания операций: связи идут через колонку `ID`.

### Дедуп

Отпечаток операции: дата, время (или 12:00:00), сумма, счета, категория, подкатегория, тип, описание, магазин, теги, комиссия.

Пропуск только если такая же операция **уже есть в учёте**. Две одинаковые строки в файле обе импортируются. Разные операции с одной датой, суммой, счётом и категорией (два автобуса, два перевода) не схлопываются.

### Системные категории

Имена вроде «Кредиты», «Подписки», «Долги», «Комиссия», «Перевод» сопоставляются с системными категориями инстанса. Новые подкатегории у них из строк операций не создаются; в секционном файле подкатегории системных категорий приходят из секции `subcategories`.

То же правило для пресета Cubux, чтобы экспорт с одного сервера не падал на другом с `system category is read-only`.

## Экспорт

`GET /api/v1/export?format=buhgalter`

Всегда полный перенос учёта: параметры `from`/`to`/`account_id`/`category_id` **игнорируются** (в отличие от Cubux). В UI экспорта фильтры скрыты, пока выбран формат «Бухгалтер».

Без `format` — Cubux (обратная совместимость API). В UI экспорта по умолчанию формат «Бухгалтер».
