# Формат Бухгалтер (импорт / экспорт)

Нативный CSV для переноса операций между инстансами Buhgalter. База колонок совпадает с [Cubux](cubux.md), плюс время, магазин и теги.

Для выгрузки в Cubux используйте формат Cubux в UI экспорта или `GET /api/v1/export?format=cubux`.

---

## Заголовки CSV

```
Тип,Дата,Сумма списания,Валюта списания,Счет списания,Сумма пополнения,Валюта назначения,Счет пополнения,Категория,Subcategory,Описание,Проект,Пользователь,Время,Магазин,Теги
```

Кодировка: **UTF-8 с BOM**. Первые 13 колонок — как в Cubux; последние три можно опустить (тогда поведение как у Cubux).

## Дополнительные колонки

| Колонка | Формат | Назначение |
|---------|--------|------------|
| `Время` | `HH:MM` или `HH:MM:SS` | Время операции (UTC, как в API). Без колонки дата ставится на 12:00 UTC |
| `Магазин` | имя | Создаётся, если нет в справочнике |
| `Теги` | имена через запятую или `;` | Создаются, если нет в справочнике |

## Импорт

`preset=buhgalter` в `POST /api/v1/import/preview`, `POST /api/v1/import`, `POST /api/v1/import/jobs`.

Файл Cubux без лишних колонок тоже принимается этим пресетом.

### Системные категории

Имена вроде «Кредиты», «Подписки», «Долги», «Комиссия», «Перевод» сопоставляются с системными категориями инстанса. Новые подкатегории у них **не создаются** (категория read-only): если подкатегория уже есть (например имя кредита), она используется, иначе операция импортируется только с категорией.

То же правило действует и для пресета Cubux, чтобы экспорт с одного сервера не падал на другом с `system category is read-only`.

Связи с сущностями (кредит, долг, подписка, комиссия перевода) из CSV не восстанавливаются — переносятся сами операции.

## Экспорт

`GET /api/v1/export?format=buhgalter&from=2025-01-01&to=2025-12-31`

Без `format` — Cubux (обратная совместимость API). В UI экспорта по умолчанию формат «Бухгалтер».
