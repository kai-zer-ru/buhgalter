## Надёжность учёта (сервер)

Patch-релиз с упором на целостность данных и предсказуемость API:

- операции, переводы, теги и балансы счёта пишутся **атомарно**;
- архивация и удаление счёта cash/bank переводит остаток и меняет статус **в одной транзакции**;
- автосписание подписок и периодических операций не «двойничает» при сбое после списания;
- платёж на кредитную карту проверяет лимит **под блокировкой** строки счёта;
- восстановление графика кредита учитывает **тип** (ипотека не пересобирается как потребкредит);
- `paid_amount` по кредиту не превышает тело при автосписании и ручном платеже;
- импорт: статус `done` только после успешной записи; `Idempotency-Key` без гонки дубля журнала;
- восстановление БД из бэкапа не удаляет `.bak`, пока новая база не открылась; при ошибке — откат на прежний файл;
- планировщик запоминает `lastRun` только после успешного списания;
- уведомления: dedup только для реально отправленных; worker не активирует `future`, если плановые уведомления выключены.

## Безопасность и доступ

- Host `localhost` / `127.0.0.1` / `::1` **не обходит** ограничение ExternalAccess с удалённого IP.
- **Не доверяем** `X-Forwarded-Host` — для проверки доступа используется `Host` (как выставляет nginx).
- **Бан** пользователя удаляет сессии **и** API-токены.
- Битый `expires_at` у API-токена считается **истёкшим** (fail-closed).
- Смена пароля отзывает **чужие** сессии (текущая cookie сохраняется; вызов через API-токен — все сессии).

Подробнее — [install/nginx.md](install/nginx.md), [api/authentication.md](api/authentication.md), [api/user-status.md](api/user-status.md).

## Плановый остаток и баланс

- В подписи планового остатка учитываются **запланированные платежи по кредитам** текущего месяца (как подписки и периодические).
- Исправлен двойной учёт: просроченная подписка **прошлого** месяца больше не суммируется со списанием **текущего** в `forecast_balance`.

## Кеш и живые обновления (веб)

- После **неудачной** мутации (4xx/5xx) сервер **не** сбрасывает GET-кеш и не шлёт лишний `invalidate` — данные на сервере не менялись ([ui-api-cache.md](ui-api-cache.md)).
- **Эпоха кеша** на сервере и в ref-cache: GET, начатый до мутации, не «заливает» устаревший ответ после инвалидации (главная, счета и список операций снова сходятся сразу).
- При первом подключении WebSocket сбрасывается ledger-кеш; dashboard обновляет `/accounts*` и балансы; для переводов — точечные `hint_paths`.

## Android

- **Офлайн:** вместо сырого текста ошибки (код, URL) — понятное «Сервер недоступен» и аналоги без технических деталей.
- **Отпечаток / PIN:** приложение реже само сворачивается после разблокировки; меньше подтормаживаний главной и drawer сразу после входа ([android-client-platform.md](android-client-platform.md)).

## Прочее (API)

- Некорректные суммы **автопополнения** счёта (`threshold` / `target`) → **400**, а не тихий ноль.
- Ошибки API по долгам и каталогам (merchant, tag, шаблоны операций) при сбое БД → **500**, не 200/201 с пустым телом.
- Бюджет: автокопирование с прошлого месяца на GET не падает с 500 при гонке; создание бюджета и периода — в одной транзакции.

## Обновление

**Сервер / Docker:** бэкап → замена бинарника или `docker compose pull && up -d`. Новых миграций БД нет. Рекомендуется **v1.7.1** и для веба, и для Android (REST без breaking changes).

**Android:** установите новый APK из [Releases](https://github.com/kai-zer-ru/buhgalter/releases) или из попапа «Версии». Фиксы офлайна и отпечатка — в APK.

**CI:** на теге `v*` сборка релиза (`goreleaser` + Docker + APK) без повторного полного CI — быстрее выход patch-версий.
