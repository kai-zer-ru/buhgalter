# Семья / команда

Группа людей на одном инстансе: владелец, участники, приглашения кодом / ссылкой / QR. Личные счета остаются личными; семейные видны всем членам (`scope=household`).

Связанно: [data-model.md](data-model.md), [feature-toggles.md](feature-toggles.md), [android-client-ui.md](android-client-ui.md), [roadmap/team-collaboration.md](../roadmap/team-collaboration.md).

## Модель

- Семья / команда — одна сущность `households` с полем `kind` (`family` | `team`, по умолчанию `family`). Служебный пользователь-принципал `users.kind = 'household'`, логин `household:{id}`. Принципал не логинится и не виден в админке / списке людей. Ограничения по типу группы появятся позже; сейчас `kind` только хранится и задаёт подписи: меню, вкладки, бейдж, тумблер «Семейный / Командный счёт», подтверждение «Сделать общим», выход / исключение / роспуск и их тосты. UI берёт `<ключ>.team` для команды (`householdKindKey`). Ошибки API и заголовок приглашения (тип ещё неизвестен) — нейтральные («семья или команда», «группа»).
- Человек (`kind = 'person'`) состоит максимум в одной семье (`UNIQUE` на `household_members.user_id`). Роли: `owner` (ровно один) и `member`.
- Инвайт: 9 символов алфавита без `0O1IL`, отображение `XXX-XXX-XXX`, TTL 7 суток, одноразовый. Ссылка `{base}/invite/{code}`; `base` — `external_url` инстанса, иначе origin запроса (`Host`, не `X-Forwarded-Host`).
- Флаг `household` (default on) закрывает только API `/households*` и `/household-invites*` и экраны UI. Данные семьи при выключении не удаляются.

## API

См. OpenAPI, тег **Household**. Кратко:

| Действие | Кто |
|----------|-----|
| `GET /households/me` | любой человек |
| `POST /households`, `PATCH /households/me`, инвайты, kick, transfer, dissolve | owner |
| `POST /household-invites/preview` и `accept` | человек без семьи |
| `POST /households/me/leave` | member |

Preview/accept: 10 попыток в минуту на пользователя. Повторно использованный / просроченный / отозванный код → `ERR_INVITE_INVALID`.

## UI

Web: `/settings/household`, accept `/settings/household/accept` и `/invite/{code}`. Без группы пункт меню — «Семья / команда»; после создания — «Семья» или «Команда» по `kind`. На пустом экране две кнопки: создать семью или команду (`POST /households` с `kind`). Без сессии `/invite/{code}` ведёт на вход с возвратом. На мобильном UA — «Открыть в приложении» (`ru.kai_zer.buhgalter://invite/{code}`). QR приглашения — с иконкой приложения в центре (коррекция `H`). В списке активных инвайтов меню «⋯»: «Показать QR» (тот же диалог) и «Отозвать».

Android: тот же экран в настройках; accept `/settings/household/accept?code=`; scheme и QR (камера / файл). Код из QR всегда гасится на **текущем** сервере. Предупреждение «чужой host» — только если в профиле задан внешний URL и host ссылки не LAN и не он. Без внешнего адреса (только LAN) QR с Host браузера (IP, `.local`, имя ПК) принимается. QR с `external_url` при заполненном remote — тот же сервер. Офлайн: экран требует сеть, membership в outbox не ставится. После смены членства, share и unshare сбрасываются ref-cache, ledger-хук и виджеты (`resetCachesAfterMembershipChange`). Смена группы на другом устройстве ловится по `GET /households/me` (id группы + состав) при warm.

## Общие счета и UI

- Бейдж «Семья» на семейных счетах (список, карточка, селекторы). Группировка: один заголовок «Личные» и один «Семья»/«Команда»; внутри каждого — «Мои средства» и «Кредитные средства», без повтора заголовка.
- Новый счёт: тумблер «Семейный счёт», если пользователь в группе. Меню «Сделать общим» / «Сделать личным» (unshare — только owner). На карточке: «Исходно: {имя}», если есть `original_owner`.
- Формы операций: справочники по `scope` выбранного счёта (`refsForAccount`); при смене счёта — сопоставление по имени или сброс с подсказкой.
- Справочники категорий / продавцов / тегов: вкладки «Личные / Семья». Главная (счета, итог, **последние операции**), статистика, бюджет: «Всё / Личное / Семья» (`catalogScope` в localStorage, `GET /transactions?scope=`). Виджеты Android всегда `scope=all`.

## Выход и роспуск

- `POST /accounts/{id}/unshare` — только owner. Счёт уходит `original_owner_user_id`, если этот человек ещё в группе; иначе 409 `ERR_UNSHARE_NO_ORIGINAL_OWNER`. Member → 403.
- Leave / kick: данные семьи не переносятся. Ушедший больше не видит семейные строки (404). Личные правила/шаблоны, ссылавшиеся на семейный счёт, теряют `account_id`; intercept-binding на семейные счета удаляются. Счёт, который ушедший отдал в семью, остаётся у семьи.
- Dissolve: `confirm_members` обязателен, если есть другие члены. Каждый семейный счёт — исходному владельцу, если он ещё член, иначе owner. Счёт, созданный сразу семейным, — owner. Принципал и его остатки удаляются. `ERR_HOUSEHOLD_HAS_SHARED_DATA` больше нет.
- Удаление пользователя в админке: member = kick + wipe личного; owner с членами → 409 `ERR_HOUSEHOLD_OWNER_DELETE`; owner без членов — dissolve, затем удаление.

## Что не входит

Несколько групп на человека, роль viewer, SSO, офлайн-очередь для share/unshare и смены membership.
