# Бюджет

Модуль планирования расходов: лимиты на категорию, подкатегорию или все расходы **за календарный месяц**, сравнение «план vs факт», копирование между месяцами, уведомления при пересечении порога.

Связанные документы: [ui-budget.md](ui-budget.md), [data-model.md](data-model.md), [ui-stats.md](ui-stats.md), [notifications.md](notifications.md), [api/openapi.yaml](api/openapi.yaml).

---

## Назначение

Бюджет не заменяет [статистику](ui-stats.md): факт (`spent`) считается из тех же `transactions`, что и `GET /stats/by-category`, с теми же фильтрами.

| | Статистика | Бюджет |
|---|------------|--------|
| Вопрос | «Сколько потратил?» | «Сколько **можно** потратить?» |
| Период | любой | календарный месяц |
| Гранулярность | категория / подкатегория | категория, подкатегория, все расходы |
| Проактивность | нет | предупреждение при пороге (по умолчанию 90%) и 100% |

---

## Scope (область лимита)

| `scope` | Описание | Уникальность в месяце |
|---------|----------|------------------------|
| `category` | Расходы с `category_id` | один бюджет на категорию |
| `subcategory` | Расходы с `subcategory_id` | один бюджет на подкатегорию |
| `all_expense` | Все операции `type = expense` | один общий бюджет |

`all_income` зарезервирован в схеме; не используется.

Опциональный `account_id` **сужает расчёт факта** (только операции по счёту той же валюты, что бюджет), но **не создаёт отдельный бюджет**: два лимита на одну категорию в одном месяце **одной валюты** невозможны. Лимит той же категории в другой валюте — отдельная строка.

Системные категории расходов в форме бюджета не выбираются. Платежи кредита с `exclude_from_stats = 1` **не входят** в факт (как в статистике).

## Помесячные записи

Каждая строка `budgets` относится к **одному** календарному месяцу:

| Поле | Описание |
|------|----------|
| `month` | `YYYY-MM` в timezone пользователя |
| `copy_forward` | `1` — сохранение уже наступившего месяца записывает следующий; 1-го числа создаётся отсутствующий следующий месяц, если флаг включён |

Бюджет **не** действует на все будущие месяцы автоматически. Просмотр другого месяца без записи в `budgets` для этого `month` — пустой список (с опцией «Скопировать» с прошлого месяца).

Миграция `038_budget_month_copy.sql`: существующим записям проставляется `month` из раннего `budget_periods` или `created_at`.

## Копирование на следующий месяц

| Способ | Поведение |
|--------|-----------|
| Сохранение с `copy_forward = true` | Если месяц бюджета уже наступил (текущий или прошлый) — в том же сохранении создаётся или обновляется **только** следующий месяц. У этой строки `copy_forward = 0`. У источника флаг остаётся как в запросе. Месяц через один не создаётся и не меняется |
| Будущий месяц | Сохранение с тумблером только включает флаг и не создаёт следующий месяц. Когда месяц наступит, сохранение с тумблером запишет следующий |
| Уже есть строка следующего месяца | Обновляются название, лимит, порог, счёт и активность. `planned_amount` периода цели становится равен новому лимиту. `rollover_amount`, операции и `budget_alert_sent` не меняются. Старые бюджеты не удаляются. Смена scope пишет новый scope следующего месяца и не удаляет старый |
| Нет строки | Создаётся копия с теми же полями и `copy_forward = 0`, в том числе неактивная. Из нескольких строк одного scope обновляется активная, иначе неактивная с более поздним `updated_at`. `account_id` не входит в идентичность |
| 1-е число | По timezone пользователя, один раз за этот локальный день: у бюджетов текущего месяца с `copy_forward = 1`, если строки следующего месяца этого scope ещё нет, создаётся она с `copy_forward = 0`. Существующую строку проход не перезаписывает и дальше одного месяца не идёт. В другие дни фон строку не создаёт и не восстанавливает удалённую. Если сервер весь этот день не работал, пропуск не догоняется: следующий месяц появится, когда владелец сохранит уже наступивший месяц с тумблером |
| Чтение | `GET /budgets`, `GET /budgets/summary` и воркер порога бюджеты не пишут |
| `POST …/budgets/{id}/copy-next` | Ручное копирование одного бюджета на месяц `month + 1`. Конфликт scope — `409 ERR_BUDGET_COPY_EXISTS` |
| `POST …/budgets/copy-from-previous?month=` | Все активные бюджеты прошлого месяца → указанный месяц (если нет конфликта) |
| UI «Скопировать» | То же, что `copy-from-previous`; видна, если в выбранном месяце нет бюджетов, а в предыдущем есть (`can_copy_from_previous`) |

Тумблер выключен (поля нет или `copy_forward = false`) — следующий месяц не меняется. После сохранения и после создания строки 1-го числа серверный GET-кеш пользователя не отдаёт старую сводку бюджетов.

Импорт файла «Бухгалтер» записывает бюджеты как в файле и не дописывает следующий месяц: каждый месяц уже есть в файле.

## Уникальность

Один **активный** бюджет на комбинацию `(user_id, scope, category_id, subcategory_id, month, currency)` — частичный уникальный индекс (`064_budget_unique_currency.sql`).

Запрещено в одном месяце **и одной валюте**:

- два `all_expense`;
- два бюджета на одну категорию (например, «Магазины»);
- два бюджета на одну подкатегорию (например, «Озон»).

Сумма лимита, порог уведомления и счёт **не** делают бюджет «другим» для целей уникальности.

API: `409 ERR_BUDGET_DUPLICATE` при создании/активации дубликата.

## Расчёт факта (`spent`)

- Период: `[period_start, period_end)` — границы месяца в `users.timezone`, UTC в БД.
- Только `kind = manual`.
- Тип: `expense`.
- **Переводы между своими счетами не учитываются:** `transfer_group_id IS NOT NULL` (в т.ч. комиссия в «Комиссия»).
- Исключение платежей кредита: `credit_payments.exclude_from_stats = 1`.
- Опционально: фильтр `account_id` из бюджета.
- Только счета с `accounts.currency = budgets.currency` (без `account_id` — все такие счета).

`planned` = `budget_periods.planned_amount` (период создаётся лениво из `budgets.amount` при первом обращении к месяцу).

`remaining` = `planned - spent` (может быть отрицательным).

`percent` = `round(spent * 100 / planned)`.

`status`:

| Значение | Условие |
|----------|---------|
| `ok` | &lt; `alert_at_percent` |
| `warning` | ≥ порога и ≤ 100% |
| `exceeded` | &gt; 100% |

## Превью факта (`GET /budgets/spent-preview`)

Считает `spent` **без** существующей строки бюджета — теми же фильтрами, что `BudgetSpent` / сводка.

| Параметр | Описание |
|----------|----------|
| `month` | `YYYY-MM`; без параметра — текущий месяц пользователя |
| `scope` | `category` \| `subcategory` \| `all_expense` |
| `category_id` | обязателен при `category` |
| `subcategory_id` | обязателен при `subcategory` |
| `account_id` | опционально сужает факт |
| `currency` | валюта факта; без счёта — выбранная на экране / профиль |

Ответ: `{ "spent", "spent_display" }`. Эндпоинт в пути содержит `/preview` — вне серверного GET-кеша и client ref-cache.

В UI формы `/budget` подсказка «Уже потрачено» показывается только для текущего или прошлого месяца.

## Сводка (`GET /budgets/summary`)

### Порядок карточек

1. `all_expense` — всегда первая.
2. Остальные — по имени (`name`).

### Дочерние суммы в общем бюджете

Для `scope = all_expense` в ответ добавляются поля (сумма по всем активным бюджетам `category` и `subcategory` **этого же месяца**):

| Поле | Смысл |
|------|--------|
| `children_planned` | Сумма лимитов дочерних бюджетов |
| `children_spent` | Сумма факта дочерних бюджетов |
| `*_display` | Форматированные строки для UI |

В UI: «По категориям: {children_spent} / {children_planned}».

### Тело ответа

```json
{
  "month": "2026-07",
  "can_copy_from_previous": false,
  "available_currencies": ["RUB", "USD"],
  "items": [ /* BudgetSummaryItem[] */ ]
}
```

Без `?currency=` — все бюджеты всех валют (виджет главной); каждая строка со своим `currency`. С `?currency=X` — только эта валюта. `children_*` у `all_expense` — дочерние той же валюты.

## Поля бюджета

| Поле | По умолчанию | Описание |
|------|--------------|----------|
| `name` | — | Отображаемое имя |
| `scope` | — | `category` \| `subcategory` \| `all_expense` |
| `amount` | — | Лимит, копейки |
| `alert_at_percent` | **90** | Порог уведомления, 0 = выкл |
| `is_active` | `true` | Неактивный не попадает в `summary` |
| `copy_forward` | `false` | Сохранение уже наступившего месяца записывает только следующий и выключает там копирование |
| `month` | текущий месяц пользователя | При `POST` — query `month` или текущий |
| `account_id` | `null` | Все счета этой валюты |
| `currency` | валюта профиля | Задаётся при создании; `PATCH` не меняет |

Редактирование `amount` обновляет `budget_periods.planned_amount` текущего месяца (query `month` в `PATCH`).

## API

```
GET    /api/v1/budgets?month=2026-06
POST   /api/v1/budgets?month=2026-06
PATCH  /api/v1/budgets/{id}?month=2026-06
DELETE /api/v1/budgets/{id}
GET    /api/v1/budgets/summary?month=2026-06
GET    /api/v1/budgets/summary?month=2026-06&currency=USD
POST   /api/v1/budgets/{id}/copy-next
POST   /api/v1/budgets/copy-from-previous?month=2026-06
```

`month` — `YYYY-MM` в timezone пользователя.

`BudgetUpsertRequest`: `name`, `scope`, `amount`, опционально `category_id`, `subcategory_id`, `account_id`, `currency` (create), `alert_at_percent`, `is_active`, `copy_forward`.

Коды ошибок: `ERR_BUDGET_DUPLICATE`, `ERR_BUDGET_COPY_EXISTS`, `ERR_BUDGET_NOTHING_TO_COPY`, `ERR_BUDGET_MONTH`, `ERR_BUDGET_SCOPE`, `ERR_CURRENCY_MISMATCH`.

## Уведомления

Триггер `budget_threshold` — см. [notifications.md](notifications.md).

Пороги: `alert_at_percent` и 100%. Дедупликация: `budget_alert_sent (budget_id, period_start, threshold_percent)`.

Hook после расходной операции и worker по расписанию пересчитывают `summary` **текущего** месяца пользователя. Этот пересчёт бюджеты не создаёт и не обновляет.

## Вне scope / позже

Подробный план (**v1.10.0**): [budget-post-mvp.md](../roadmap/budget-post-mvp.md). Решения на реализацию зафиксированы там (и в `bmad_docs/specs/spec-budget-post-mvp/`).

| Тема | Суть |
|------|------|
| **Прогноз** | `spent` + все ожидаемые расходы до конца месяца в scope (периодические, подписки, future, кредиты, долги и аналоги); не путать с `forecast_balance` на главной |
| **Rollover** | перенос непотраченного (`max(0, planned − spent)` → `rollover_amount`); смена флага mid-month не трогает уже записанный перенос; не путать с `copy_forward` |
| **Конверт / доступно** | `planned + rollover − spent`; percent/status/алерты от `planned + rollover` |
| **К распределению** | упрощённый zero-based из доходов месяца — в том же релизе v1.9 |
| Бюджет на доход | `all_income` — вне этого пункта |
| Группы категорий | один лимит на набор категорий — вне этого пункта |
| Комиссии в факт | сейчас расходы с `transfer_group_id` / системные исключены |

Виджет на главной — [ui-budget.md](ui-budget.md#виджет-на-главной).
