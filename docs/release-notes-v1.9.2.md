## Магазины: несколько имён

На странице **Магазины** у записи одно **основное имя** и несколько **алиасов** (через запятую) — и при создании, и при правке.

Уже заведённые дубли можно **объединить**: действие у магазина, который остаётся. Имена и алиасы остальных становятся его алиасами, операции переезжают на него. Имя и иконка оставшегося магазина не меняются. В журнале у этих операций одно название — основное имя.

В форме операции поиск идёт по основному имени и по алиасам. Совпадение с алиасом выбирает этот магазин. В списке операций и в выбранном значении видно только основное имя.

То же имя при создании операции и при импорте находит магазин по алиасу. Экспорт «Бухгалтер» увозит алиасы и привозит их обратно. Старый файл без колонки алиасов по-прежнему читается.

Подробнее — [merchant-aliases.md](../roadmap/merchant-aliases.md), [data-model.md](data-model.md).

## Кнопки в шаблоне уведомления

В **Настройки → Уведомления** (только **web**) кнопки по умолчанию Telegram и MAX стоят в раскладке **каждого** шаблона.

Их можно перетаскивать между рядами и внутри ряда. Удалить из шаблона нельзя: пока кнопка задана в блоке «Кнопки по умолчанию», она есть в исходящем сообщении. Текст, тип и поля правятся только там и сразу те же во всех шаблонах. Свои кнопки шаблона по-прежнему добавляются и удаляются.

Новая кнопка по умолчанию, которой ещё нет в сохранённом порядке шаблона, встаёт в конец раскладки (перед блоком недостатка средств, если он дописывается). Если свой порядок ещё не сохраняли, отправка как раньше: сначала общие кнопки, потом кнопки шаблона.

В блоке «Кнопки по умолчанию» конструктор только у **включённого** канала. Оба включены — переключатель вкладками. Выключенный канал при сохранении этого блока свою клавиатуру не затирает.

Подробнее — [notifications.md](notifications.md), [notification-template-global-buttons.md](../roadmap/notification-template-global-buttons.md).

## Экспорт без `format`

`GET /api/v1/export` без параметра `format` (пустая строка и пробелы — тоже) отдаёт секционный CSV **«Бухгалтер»** (`#BUHGALTER,1`), полный перенос учёта. Фильтры `from`, `to`, `account_id`, `category_id` у этого формата не применяются.

Cubux — явный `format=cubux`. Неизвестное значение (`format=foo`) по-прежнему Cubux: опечатка не выгружает весь учёт.

Экран импорта/экспорта не менялся: радиокнопка по умолчанию уже «Бухгалтер», скачивание уже передаёт `format`. Затронуты вызовы API, где `format` не указывали — раньше они получали CSV Cubux.

Подробнее — [import/buhgalter.md](import/buhgalter.md), [import/cubux.md](import/cubux.md).

## Android

В хабе **Настройки** нет пункта «Уведомления»: каналы, шаблоны и кнопки Telegram/MAX настраиваются в вебе. **Банковские уведомления** и черновики перехвата на месте. Страница по прямому адресу по-прежнему показывает баннер «Настройте уведомления в веб-версии».

Поиск магазина в форме — по основному имени и алиасам, как в вебе.

## Обновление

**Сервер / Docker:** бэкап → замена бинарника или `docker compose pull && up -d`. Миграция `056` применится при старте. Для алиасов, объединения магазинов, порядка кнопок и нового умолчания экспорта нужен сервер **≥ 1.9.2**. Версия сборки **1.9.2**.

**Веб:** встроен в бинарник/образ сервера.

**Android:** новый APK из [Releases](https://github.com/kai-zer-ru/buhgalter/releases) или из попапа «Версии» — скрытый пункт настроек и поиск по алиасам в форме. Журнал и так показывает основное имя с сервера.

## Для разработчиков

- OpenAPI / версия сборки **1.9.2**. Миграция `056_merchant_aliases`.
- `aliases` у магазина в `GET /merchants` и `GET /ui/meta`; `POST /merchants/{id}/merge`.
