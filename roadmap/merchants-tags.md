# Магазины (контрагенты), теги и комментарий

Планируется в **v1.5.0** ([ROADMAP](../ROADMAP.md#v150)).

Часть обогащения операций. Разбивка одной оплаты на несколько счетов — отдельно: [transaction-split-accounts.md](transaction-split-accounts.md) (v1.6.0). Вложения/фото к операции — вместе со [сканером чеков](receipt-scanner.md).

## Зачем

Сейчас у операции есть свободное **описание** (`description`). Нет нормализованного «магазина» и меток — плохо для фильтров и статистики «куда уходит».

## Решения

| Тема | Решение |
|------|---------|
| Комментарий | Отдельное поле **не вводим**. Хватает `description` (в UI — описание / комментарий). |
| Теги | Отдельная сущность + M2M с операцией. Ручной ввод, сохранение в справочник, выбор по совпадению ввода (autocomplete). |
| Магазин | Отдельная сущность: CRUD + на форме операции выбор из списка или создание новой строки (как подкатегория). |
| Из чека | **Не в этом пункте.** Prefill магазина из данных чека — после реализации [сканера чеков](receipt-scanner.md). |

## Scope (v1.5.0)

Feature flag: `merchants_tags` (см. [feature-toggles.md](feature-toggles.md)).

| Поле | Суть |
|------|------|
| Магазин / контрагент | Справочник пользователя (`merchants`); `transactions.merchant_id`; фильтр в списке |
| Теги | Несколько меток на операцию; `tags` + `transaction_tags`; фильтр `?tag_id=` |
| Комментарий | Существующее поле `description` |

Пример: оплата наличными за автобус — магазин не обязателен; теги «транспорт» / «отпуск». Покупка в магазине — магазин из справочника + теги + описание.

## MVP

1. Справочник магазинов + поле на операции (выбор или inline-создание по имени) + фильтр в списке.
2. Теги many-to-many + autocomplete + фильтр `?tag_id=`.
3. Описание без новой колонки (`description`).
4. Web + Android: форма операции, фильтры, лёгкий CRUD в настройках.

## Не входит в этот пункт

- Prefill магазина из чека / ФНС (см. Follow-up).
- Разбивка суммы на несколько счетов/категорий ([transaction-split-accounts.md](transaction-split-accounts.md)).
- Полноценный CRM контрагентов.
- Автосоздание магазина из банка без подтверждения.
- Отдельный `/stats/by-merchant` (фильтры stats по `merchant_id` / `tag_id` — по возможности).

## Follow-up

- После реализации [сканера чеков](receipt-scanner.md): при импорте/prefill чека подставлять предложенный магазин (`merchant_name` / выбор из справочника), пользователь подтверждает перед сохранением.
- Prefill магазина из [перехвата уведомлений](notification-intercept.md) — тот же паттерн (match справочника или имя на форме, без автосоздания).
