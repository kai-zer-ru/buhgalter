# Алиасы магазинов

Патч **v1.9.2** к справочнику магазинов (v1.5).

## Зачем

Один и тот же магазин в выписке и в чеке называется по-разному. Сейчас каждое написание — отдельная запись, а в форме операции ищется только основное имя.

## Делаем

- У магазина одно **основное имя** и несколько **алиасов**.
- Уже созданные магазины можно **объединить**: выбранный остаётся, имена и алиасы остальных становятся его алиасами, операции переезжают на него. После этого у всех этих операций в журнале одно общее название — основное имя оставшегося магазина.
- В форме новой/редактируемой операции поиск идёт по основному имени **и** по всем алиасам. Совпадение с алиасом выбирает этот магазин, а не создаёт второй.
- В списке операций, в выбранном значении и в `merchant_name` API — **только основное имя**.
- То же имя на сервере (создание операции по `merchant_name`, импорт) находит магазин по алиасу.
- Экспорт «Бухгалтер» увозит алиасы и привозит их обратно. Старый файл без колонки алиасов по-прежнему читается.
- Алиасы задаются и при создании магазина, и при редактировании. «Объединить» — действие у магазина, который остаётся: выбираются другие, подтверждение, их имена становятся алиасами.
- Список магазинов в API (`GET /merchants` и `GET /ui/meta`) отдаёт алиасы вместе с основным именем.

## Не делаем

- Показ алиаса отдельной строкой в журнале и в фильтре операций.
- Отдельный магазин на каждый алиас.
- Импорт Cubux.
